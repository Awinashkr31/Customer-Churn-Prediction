# Customer Churn Prediction

Predicting which telecom customers are likely to cancel their subscription (churn), so the business can step in with retention offers *before* they leave.

## Problem

Acquiring a new customer costs far more than keeping an existing one. This project builds a binary classifier that flags customers at risk of churning, using their demographics, account history and subscribed services. A model that catches most churners (high recall) — even at the cost of some false alarms — is more valuable here than one that is merely "accurate", because a missed churner is lost revenue while a false alarm only costs a retention offer.

## Dataset

**IBM Telco Customer Churn** — IBM sample data with 7,043 fictional telecom customers, each described by 19 features (tenure, contract type, internet/phone services, monthly & total charges, payment method, …) plus the target label `Churn`.

- Source: IBM's official GitHub repo — https://github.com/IBM/telco-customer-churn-on-icp4d/blob/master/data/Telco-Customer-Churn.csv
- After cleaning (see below): **7,032 customers**, of which **1,869 churned — a churn rate of 26.58%**.

## Approach

The whole flow lives in one reproducible script, `churn_prediction.py`:

1. **Cleaning** — `TotalCharges` arrives as text and is blank for 11 brand-new customers (tenure 0); it is converted to numeric and those 11 rows are dropped. `customerID` is dropped as an identifier, not a feature.
2. **EDA** — churn rate, tenure range, and average monthly charges for churners (74.44) vs. stayers (61.31) are summarised.
3. **Preprocessing** — an sklearn `ColumnTransformer` inside a `Pipeline` (no leakage): median imputation + standard scaling for numeric features, most-frequent imputation + one-hot encoding for categoricals.
4. **Split** — stratified 80/20 train/test split (5,625 train / 1,407 test, `random_state=42`).
5. **Models** — Logistic Regression, Random Forest (300 trees) and XGBoost (300 trees). Because churners are the minority class, `class_weight="balanced"` / `scale_pos_weight` are used so the models do not ignore them.
6. **Evaluation & selection** — accuracy, precision, recall, F1, ROC-AUC and confusion matrix on the held-out test set; the best model is selected by **F1-score**, the balanced metric that matters for an imbalanced problem like this.

## Results

Measured on the held-out test set (1,407 customers) from the actual run — full details in [`results/metrics.json`](results/metrics.json), raw console log in [`results/run_output.txt`](results/run_output.txt):

| Model | Accuracy | Precision | Recall | F1-score | ROC-AUC |
|---|---|---|---|---|---|
| **Logistic Regression** ✅ | 0.7257 | 0.4901 | **0.7968** | **0.6069** | **0.8351** |
| Random Forest | **0.7626** | **0.5455** | 0.6417 | 0.5897 | 0.8139 |
| XGBoost | 0.7413 | 0.5095 | 0.7193 | 0.5965 | 0.8190 |

**Best model: Logistic Regression** (highest F1, 0.6069; ROC-AUC 0.8351). Its confusion matrix on the test set:

| | Predicted: stay | Predicted: churn |
|---|---|---|
| **Actually stayed** | 723 (TN) | 310 (FP) |
| **Actually churned** | 76 (FN) | 298 (TP) |

It catches ~80% of all churners (recall 0.7968) — exactly the trade-off a retention team wants.

**Top churn drivers** (Random Forest feature importance): `TotalCharges` (0.141), `tenure` (0.133), `MonthlyCharges` (0.122), month-to-month contract (0.075), no online security (0.037), two-year contract (0.036), no tech support (0.030), electronic-check payment (0.028), fibre-optic service (0.027), no online backup (0.017). In plain words: newer, month-to-month customers paying more per month, without support/security add-ons, churn the most.

The trained best-model pipeline is saved to `models/best_churn_model.pkl` (joblib) by the script.

## How to run

```bash
pip install -r requirements.txt
python churn_prediction.py
```

If `data/Telco-Customer-Churn.csv` is not present, the script downloads it from the IBM source above automatically. Outputs: printed metrics, `results/metrics.json`, and the saved model in `models/`.
